# 对话约束重整规划

日期：2026-11-07；更新：2026-11-08。状态：四阶段的工程实现、回归与有限模型评阅已交付，见[完整交付说明](dialogue-policy-completion.md)和[评阅记录](dialogue-policy-evaluation.md)。真人长期偏好未由开发侧抽查代替；双端与同步计划保持暂缓。

## 目标与判断

产品主线是“持续角色陪伴＋共同活动”。对话应允许依鸣有情绪、偏好、反应差异、自发念头和自己的生活，而不只输出正确、礼貌、克制的回答。

上一轮对连续自我分析进行了止血，但部分办法过于保守。应当阻断的是重复输入引起的无事件情绪升级、推演冒充事实和重复投递；不能把害羞、委屈、解释、主动补充或细节描写本身都视为错误。

本方案基于当前源码检查。它不代表已验证的新效果，也不承诺通过一套提示词彻底消除模型错误。

## 当前约束的问题

| 现有位置或规则 | 原本解决的问题 | 可能的副作用 | 调整方向 |
|---|---|---|---|
| `brain/dialogue_context.py` 按关键词附加表达反馈指令 | 被说像 AI 后长篇自辩 | 玩笑、认真质疑和真实受伤都套用同一回应方式 | 结合上下文理解反馈，允许重新表达、解释、打趣或不同意；不自动触发道歉或情绪归零 |
| `reply_state_zip` 不提供内心与轨迹 | 防止旧自卑叙述变成台词脚本 | 回复可能失去情感动因与细微矛盾 | 提供简短、带来源与时间的当前情绪和意图，原始长轨迹不直接注入 |
| 空闲提示禁止逐轮加重自卑、委屈 | 防止同一句反馈被反复当作新伤害 | 若泛化为不得受伤，会使角色没有情绪 | 限制同一事件重复计入和无因累积，允许有原因、有持续时间的情绪 |
| `core/proactive.py` 统一 600 秒及未回应抑制 | 防止连续独白与刷屏 | 对正在共同活动、自然补句和新事件一刀切 | 将防刷屏上限与内容事件、会话状态、用户偏好分开 |
| `SCENE_RULES`、YAML、回复上下文重复描述时空限制 | 减少地点与时间冲突 | 规则冗余、互相覆盖，角色时刻像在审核自己 | 以结构化事实与一份边界规则为准，按当前请求只附加相关信息 |
| 远程模式与故事联系方式绑定 | 防止虚构微信等外部行动 | 网页上明明在聊天，故事媒介却退回未知 | 分开实际通信渠道、故事空间与已授权外部能力 |
| 动作简短、闲聊一到三句、表情符号全面禁止 | 统一初版风格 | 风格差异变成违规，表现手段有限 | 改为作者或用户可调的风格默认值，保持角色一致性即可 |

## 四层规则

### 一、事实与能力边界：由程序尽量保证

保留以下确定性边界：后端时钟、消息及存档一致性、工具是否执行成功、真实设备能力、用户是否实际参与、哪些承诺经用户接受。

角色不能通过台词改变这些结果。提议一起出门不是双方已出门；说想提醒不等于已建立提醒；角色“看了看手机”的虚构动作不表示实际读取了用户设备。

来源也要区分：用户自述、角色说过的话、实际工具结果、已提交的虚构世界事件、角色猜想。程序确认“用户说了某件事”，不等于独立验证了那件现实事实；普通聊天也不应因此不断质疑用户。

这层不承担固定句长、情绪管理、亲疏程度和礼貌模板。无法确定、与眼前话题无关的信息不主动盘问。

### 二、角色创作空间：允许生成，并保持连续

允许角色生成自己的感受、打算、注意力、措辞、小动作及低影响生活细节。例如犹豫片刻、揉眼睛、想去观鸟、嫌一道题烦，不要求先有工具证据。

区分三个强度：

- **表达细节**：只影响这句话，不改变用户行为、资源、位置和活动结果。直接允许，无需逐项确认。
- **候选生活行动**：角色想离开、准备整理资料、想明天去某处。作为意图持续存在，可修改或放弃，不提前宣称完成。
- **持久世界事件**：角色确实换了地点、完成自己的活动、获得一份材料。由现有运行时校验时间、地点和前置条件后记录为虚构世界事件；随后才作为角色世界的既有经历引用。这仍不证明现实世界发生了对应事情。

用户参与、共同经历和已接受的约定不得随角色创作自动生成。真实天气、真实课程表及用户现实经历也不属于可自由补写的生活细节。

目前完整的角色生活事件系统尚不存在。先用现有场景与活动做有限事件记录；未提交的离线推演继续保持候选，不在这一轮扩展完整校园模拟。

### 三、表达偏好：给方向，允许偏离

默认自然接话，但允许岔开一个有关联的话题、开玩笑、停顿、不同意、短暂冷淡或认真说一段。长度由内容、情绪、熟悉程度与交流场景共同决定，不用固定句数评分。

“不机械自责”改成“不要把已处理的同一句话反复解释为新的否定”。可以委屈，但不能在没有新事件时因每次心跳继续加深；可以解释，但不必每轮证明自己像人；可以主动，但不要求任何时刻都有话。

用户反馈说话怪时，不强制某个答案。玩笑可以接玩笑，表达不清可以重说，确有误会可以解释；用户认真讨论角色感受时，也允许展开。当前关键词正则最多作为辅助信号，不能决定情绪和回应路线。

颜文字、轻微动作、口头语及长短偏好改为可调风格项。第一版在配置中管理，不立即增加一屏用户设置；不为展示个性强行塞入符号或动作。

### 四、投递与节奏：管理消息，而非压制性格

保留静默、勿扰、睡眠、用户输入优先、存读档暂停及防重复等门槛，但不把它们变成人物胆怯或关系陌生的理由。

按语义组织主动内容：

| 情况 | 计划行为 |
|---|---|
| 同一轮的一句自然补充 | 合并到同一回复或同一轮消息预算，不另起一次主动自我分析 |
| 无新事件，只想重新解释旧反馈 | 不发送，避免循环 |
| 共同活动出现实际进度变化 | 可以形成事件触发消息，是否打扰由用户偏好与活动状态决定 |
| 用户没有回应普通主动消息 | 默认等待；后续新生活细节先累积，回来后选择性自然提及 |
| 已经确认且允许发送的定时提醒 | 独立按提醒任务与渠道规则执行，不因普通闲聊未回应永久失效 |
| 离线期间多件事情 | 合并、过期丢弃或返回时呈现，不重连刷屏 |

默认仍保留低打扰策略。新增事件不能成为绕过预算的借口：由持久事件 ID、语义去重、现实时间滚动预算和任务状态共同控制，不能只让模型填写“重要”就突破限制。

600 秒先作为现版本的止血默认值保留。新方案先记录“为什么想发、为什么未发、是否同一事件”，再比较不同节奏；不直接换成更短的全局常数。优先用现有轮次、活动和服务任务承载，不先建设新消息平台。

## 状态与记忆的整理

回复前提供一个短的“当前角色视角”，建议包括当前情绪及触发事件、还想说或想做的事、当前关注对象，以及最多少量与本轮有关的关系线索。

保留原始 PAD 和旧轨迹用于兼容、观察及调试，但不把所有旧独白原样塞进回复。新增信息区分：

- `emotion_basis`：哪个已知事件影响情绪；同一事件不能在空闲心跳反复累计伤害。
- `current_intent`：角色自己的候选意图，有产生时间、进度和失效条件。
- `attention`：正在关注的话题、材料或活动。
- `beliefs`：角色推测或主观理解，可以出错并被修正，不自动升级为事实。
- `open_threads`：尚未解决的问题或已确认的安排，只按有来源的事件推进。

以上为候选字段，实施时以最小数据结构为准。新视角摘要优先在现有状态模型调用中生成，不每轮额外增加一个“审查模型”。情绪消退由时间和事件处理；不要求每轮冷静，也不让负面状态因文本回灌而无限自我强化。

记忆不只保存客观事项，也应容纳“角色当时怎样感受、偏好如何变化”。但“依鸣觉得用户不耐烦”必须保持主观解释，不能写成“用户厌烦依鸣”的确定事实。旧记忆不删除、不整体洗白，新字段向后兼容。

## 提示词与执行流程

将分散规则整理为：稳定人设 → 一份事实边界 → 本轮结构化事实 → 简短角色视角 → 本轮确需的任务信息 → 原始对话与相关记忆。

实际发送顺序仍需确保高优先级事实一致，不能依靠多个地方不断追加相反规则纠偏。旧的卷内自定义 YAML 也要可预览迁移差异、保留备份，不静默覆盖。

先梳理已有 `CORE_PERSONA`、`SYSTEM_PROMPT`、`SCENE_RULES`、回复注入、主动注入和工作记忆注入，列出规则的唯一归属。不会把所有限制删掉，再靠回复后重写补救。

硬校验负责结构和已执行动作；语言上的重复、语气和动作密度主要交给上下文与评测。不使用敏感词黑名单反复擦除角色表达；不每次遇到负面情绪都二次请求模型改得更温柔。

## 实施顺序与验收

### 第一阶段：先放开表达，保持事实底座

移除关键词触发的固定回应路线；将绝对风格禁令改为默认偏好；引入简短当前视角，恢复有来源的情绪与意图；去重现有规则。先保留当前主动投递防刷屏机制和状态结构兼容，便于单独评估表达变化。

验收：同一组上下文可出现自然差异；允许短暂委屈、玩笑和不同意见；不循环自责、不重新介绍自己，不虚构用户参与。现有保存、TTS 推理隔离、时钟及读档测试继续通过。

### 第二阶段：整理情绪与虚构生活的持续性

对同一情绪事件只更新一次；分开感受、意图、猜想与已记录生活事件。先覆盖观鸟、学习或整理材料中的一种角色自有活动，不扩大地图与多角色系统。

验收：多次空闲更新不自动加重同一条反馈；角色自己的小事有起因、变化和后续可提及内容；不会写成用户共同经历，不将猜想存成用户事实。

### 第三阶段：替换统一主动节流

在已有轮次和活动之上增加事件归属、语义去重与投递预算，逐步替换统一十分钟规则。先支持普通闲聊和一种共同活动，提醒任务保持独立语义。

验收：能自然补一句或回应活动变化；无人回应不连续倾诉；勿扰与离线不刷屏；重启、读档和重连不产生重复投递。每次未发都有可检查的内部原因，但不把诊断播报进对白。

### 第四阶段：固定上下文对照，再做实际陪伴观察

先制作至少 12 组固定场景，每组包含多轮而非只看一句话：玩笑式吐槽、认真指出问题、对方沉默、明确不同意见、脆弱表达、热烈闲聊、未知位置、已确认面对面、长间隔返回、角色自有计划、共同材料和工具失败。

自动测试验证可确定的边界，不用“必须道歉”“不得委屈”“回复少于三句”等断言评价活人感。人工对照当前版本与新版本，尽可能隐藏版本名，评价接话、个性、情感动因、连续性、主动意愿、重复和事实冲突。

小规模真实模型抽查采用相同模型、参数与初始上下文，记录随机性；模拟模型只证明流程工作，不能证明人物自然。先获得用户实际偏好，再决定节奏默认值，不用单个样例宣布优化成功。

## 发布与回退

按表达上下文、状态视角和投递策略分别保留版本开关；对旧字段优先附加与兼容读取，不破坏现有聊天、存档和记忆。先在独立测试世界对照，不把测试台词写入真实世界。每个阶段单独交付变化、样例、测试与回退方式。

第一阶段优先级最高：先让她能自然表达自己的感受与想法，再扩展会主动发生的生活。按阶段测试和发布，保留现有角色世界与回退路径。
