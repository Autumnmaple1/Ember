## 如何使用

- **专注陪伴**：选择时长后点击开始。个人计时不表示角色已经同意共同活动；共同自习需主动勾选，并选择已保存的角色回复作为确认来源。支持暂停、继续、完成、提前结束，以及可选回顾。
- **勿扰**：关闭角色主动发言，世界仍会演化，用户主动输入仍正常回复。
- **暂停世界**：在设置的“时间与后台运行”中操作，同时冻结逻辑时钟和自主演化。恢复后再继续对话。自习计时使用现实单调时间，不受世界倍率或世界暂停影响。
- **回忆**：可以按关键词和世界日期搜索对话，从结果定位原始上下文、收藏或整理约定。约定初始为待确认，空白时间和地点保持未知。用户整理的记录不自动变成角色的长期记忆。
- **角色记忆**：明确标为模型整理。可生成核对/更正草稿，经正常对话处理，不把前端编辑当作角色已经接受纠正。
- **草稿**：同一世界刷新后保留；世界改变后隔离旧草稿，并提供“取回旧草稿”。取回只填入输入框，不自动发送。已有新草稿会保留并与取回内容换行合并。
- **声音**：同一浏览器以 Web Locks 协调自动播放所有权；手动重播可接管。其他页面收到接管信号会停止当前声音。缺少 Web Locks 的环境关闭自动争用，只允许明确的手动播放。
- **存档**：先预览角色、世界时间、地点和消息统计；确认后等待实际阶段完成。当前不可安全取消的步骤不会显示假取消。任务可通过刷新列表和后台状态重新核对。

## 状态与存储

新增 `config/experience.json`，原子保存玩家收藏、约定、活动和勿扰偏好。该文件是运行数据，已排除 Git；存档会包含它。旧存档没有此文件时恢复为空记录，不携带当前时间线的活动进入旧世界。

活动使用后端单调时间计算现实耗时，轮询和心跳执行检查点。后端重启或读档后，进行中的活动会暂停，需明确继续；不会凭空累计未知离线学习成果。完成与中断必须由玩家操作，不因计时到点自动宣称完成了某项学习。

新增 `data/state/archive-job.json`，保存最近任务标识、阶段、修订号和结果。异常退出时如果上次正在读档，会保留恢复要求；世界保持暂停，界面显示恢复入口。该任务记录不作为剧情存档内容。

聊天和长期记忆继续使用现有 PostgreSQL/Neo4j，未为本次功能迁移业务库或改写已有聊天。新增收藏来源只从已保存的消息读取，拒绝伪造不存在的来源。

存档压缩先写同目录临时文件，完整关闭后再替换目标；写入失败保留上一份有效存档。有校验和的存档在导入前校验内容。缺少必要回滚表、数据库恢复失败或状态重建失败，不能报告读档成功。

## 验证记录

- Python 完整回归：**172 项通过**。包含隔离 PostgreSQL/pgvector、真实存档往返、旧档兼容、失败导入回滚、压缩失败保留旧档、损坏校验和、路径限制、并发快照/进度、跨重启保留恢复要求以及停止竞态。
- 前端单元：**24 项通过**。包含纪元隔离、旧快照/旧任务回退防护、完整历史恢复、等待播放所有权时停止，以及已有输入/声音流程。
- 浏览器：三组共 **29 类场景通过**，覆盖三种视图的 5 个宽度组合；来源定位后阅读锚点、同世界刷新草稿、跨世界手动取回均有检查。
- 1000 条合成消息整批渲染：本机最后一次快速验收约 **701 ms**；不是其他设备的性能保证。
- 真实模型抽查：两轮合成对话通过，正确区分角色在“测试图书馆”、用户在“测试宿舍”、微信远程交流，以及个人自习计时。未读取用户聊天或访问业务数据库。
- lint 与生产构建通过。主应用脚本约 240 KB（gzip 约 77 KB），角色模块约 871 KB 单独加载；这不表示总资源下载量减少到 240 KB。角色模块仍有大包提示。
- 对主要文字/纸面、次级文字/纸面、强调按钮和错误提示的配色计算，浅色比值为 5.06–11.70，深色为 7.07–11.13。该计算不替代背景图叠加、真实字幕或完整无障碍研究。
- 连续稳定性验收通过：真实运行 **1800 秒**，355 条合成回复，始终 1 个角色 Canvas、声音并发最多 1、全局监听器始终 8；30 个样本中的 JS 堆约 9.6–14.5 MB，世界重建后能回落。报告在本地 `frontend/test-results/soak-report.json`，不等价于全部 GPU/进程资源测量。

自动测试没有清空业务库。Docker 启动故障期间，使用独立 WSL PostgreSQL 14.24 + pgvector 0.8.1、端口 `55433` 完成数据库验证；测试框架创建并清理 `ember_test_*` 数据库。CI 沿用现有 pgvector PostgreSQL 16 服务。

## 启动与回退

1. Docker 就绪后，保持现有业务数据库配置（原 `127.0.0.1:5433`）。后端在 Ember 环境执行 `python server.py`。
2. 前端执行 `npm run dev`，或运行 `npm run build` 部署构建结果。前后端需配套更新，以启用纪元、活动和任务协议。
3. 打开页面，核对服务状态；查看当前情境后再开始对话。旧存档可读取，恢复后先检查位置、交流方式和活动暂停状态。
4. 回退时先等待当前任务完成并关闭后端，备份 `config/experience.json` 与存档目录，再恢复到基线提交的前后端代码并重新构建。基线会忽略新体验记录；保留文件即可，避免用旧代码覆盖含新活动记录的存档。
5. 不需要删除数据库卷或修改数据库密码。新功能没有增加业务数据表。

临时测试服务的启动/停止脚本在 `utils/start_isolated_test_postgres.sh` 和 `utils/stop_isolated_test_postgres.sh`，只面向 WSL Ubuntu 测试，文件解包至 `/var/tmp/ember-pg.*`，不安装系统包。运行测试时的 PG 环境变量只在测试进程中设置。
