# Ember 中期提交总体规划

日期：2026-11-02。功能基线：e9634bc8。提交对象：项目中期评审。

## 产品决定

沿用“持续角色陪伴＋共同活动”。以单角色依鸣为入口，让用户在对话之外共同完成一件可保存、可回顾、可继续的小事。中期验证交互闭环，不以通用自主 Agent、完整恋爱游戏或云端全天候运行作为已完成目标。

本次主线为：确认此刻 → 对话邀请 → 完成《窗边的一页》 → 收藏与回顾 → 存档 → 恢复继续。自习、约定和三层记忆作为支撑能力。

## 交付内容

1. 可运行展示包：真实 React 界面、真实共同活动规则与玩家记录；对话使用明确标注的预设台词，记忆页使用合成样例。不需要模型密钥或业务数据库。运行数据只写入展示目录。
2. 真实模型模式：保留本项目源代码、依赖与配置样例，提供隔离运行说明；模型、向量数据库、语音的效果和外部依赖单独说明。
3. 策划案：可编辑 Word、PDF 和内容源文件。包括产品定位、玩法、交互、架构、完成情况、验证证据、后续迭代与风险。
4. 演示讲稿：按约 7 分钟组织，包含操作、讲解、可观察结果和失败时的处理。
5. 验收报告与版本清单：列出本次实际运行的检查及历史验证范围。压缩包不包含密钥、私人聊天、数据库备份、开发缓存或运行中的业务状态。

## 执行顺序

先核查代码与能力边界；再制作隔离展示入口、构建前端并实测完整路径；随后用实际界面和结果编写策划案与讲稿；最后渲染检查 Word/PDF，解压验证提交包并检查内容安全。

## 中期验收标准

- 解压后按说明可启动，页面持续显示展示模式的边界说明。
- 对话流式输出后保留历史；刷新仍存在；明确失败状态可读。
- 《窗边的一页》使用生产规则完成两次选择与成果编辑，并保留成果和来源。
- 收藏、约定、自习、存读档可操作；展示存档只作用于合成数据，不冒充生产存档。
- Word 和 PDF 内容一致且逐页检查，无文字溢出或缺字。
- 材料区分当前实现、展示适配、历史验证和未完成规划，不虚构用户研究或真实模型测试。

## 后续产品优先级

第一阶段用 5 至 8 位目标用户检验“愿不愿再次回来继续这件事”；第二阶段扩展跨日共同项目和有来源的关系回顾；第三阶段才推进受保护的常驻服务与手机入口。每阶段均以可观察的验收条件决定是否继续，而不先扩充人格或地图规模。
