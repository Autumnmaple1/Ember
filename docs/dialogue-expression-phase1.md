# 对话表达重整：第一阶段交付

日期：2026-11-07。对应[对话约束重整规划](dialogue-policy-redesign.md)第一阶段。情绪事件去重、角色生活事件和主动投递重构仍待后续实施。

## 现在改变了什么

新增 `expressive_v1` 表达层，默认启用。移除按关键词触发的固定表达反馈路线，允许模型结合上下文选择重新表达、解释、玩笑或不同看法。没有增加“必须道歉”“必须温柔”等固定回应。

现有默认人设中的固定句数、全面禁用符号、动作只能一句和只能温和反对等要求，改为表达偏好。低 D 值不再直接等同于自卑和顺从。可以认真说一段、短暂不快、有原因地委屈，也可以轻松接话。

事实与能力边界继续保留：不把推测称作实际工具结果，不代替用户决定、移动或参加活动；具体个人往事同样需要记忆或世界记录。可以即时创作的是当下轻微动作、感受和候选打算，不凭空补出“上次在某地见过某物”。

## 当前视角如何进入回复

现有状态模型请求中附加可选 `reply_perspective`，包含 `feeling`、`intent`、`attention`。每项最多 120 字，程序填写逻辑时间与生成来源；不接受模型自填来源与时间作为事实。

新视角与状态一起校验、保存，再提供给回复。它明确是主观感受和候选意图，不证明用户内心，也不代表行动已经完成。旧的内心与长轨迹仍保留在状态及观察信息中，不整段回灌成对白。

旧格式状态模型没有输出新字段时，只能从本次返回的内心、目标生成短视角，不将原状态中遗漏的旧字段重新盖时间戳。可选字段无效时不会使必要状态保存失败；生成失败回退、未来时间及超过 30 个世界分钟的视角不作为当前感受注入。这个时效是表达层的暂定保护，不代表情绪必然在 30 分钟后消失；后续由事件与情绪持续性模型替代。

没有新增每轮模型调用，也没有增加回复后重写。主动发言默认十分钟现实间隔、未回应不补发的机制保持现状；本阶段只调整表达上下文，便于独立观察。

## 现有人设与风格配置

程序只对已知旧默认句做精确的内存适配，不改写 YAML 文件、不删除自定义段落、不重置角色状态。当前仓库 YAML 保留兼容原句，并注明有效表达层；实际送模文本可预览。非默认的自定义明确表达风格优先于新默认偏好。

可在本机 `.env` 或容器 `deploy/service.env` 配置：

```dotenv
DIALOGUE_POLICY=expressive_v1
```

可在正在使用的 `config/prompts.yaml` 增加以下可选项；不填时使用下列默认值：

```yaml
dialogue_style:
  symbols: occasional # occasional / none
  actions: natural # natural / none
  length: adaptive # adaptive / brief / expansive
```

容器的人设文件在运行数据卷 `/runtime/config/prompts.yaml`，并非更新镜像时覆盖。调整前保留原文件备份；启动时读取配置。`/config` 会返回表达版本、默认风格及已识别的旧默认句适配数量，不返回人设全文。

预览不会访问数据库或模型，也不会修改源文件：

```powershell
python utils/preview_dialogue_policy.py --prompts config/prompts.yaml
```

差异及有效文本输出至 Git 忽略的 `output/dialogue-expression/`。真实运行配置已预览，识别到 9 处默认句适配；其余内容保持不变。

## 验证与实际观察

完整后端隔离回归 **334 项通过**，前端单元 **32 项**与 lint 通过。最终事实边界文字调整后，表达层 **18 项**定向检查再次通过。测试覆盖原始用户输入不变、无固定反馈路线、旧版切换、风格配置错误、视角来源和时间、与状态一起持久化、坏字段兼容、过期/未来视角和失败回退；保持现有工具、记忆、读档及思考内容隔离检查。

准备了 12 组固定合成情境，包括玩笑、认真反馈、分歧、安静陪伴、脆弱表达、兴奋分享、未知位置、面对面、跨日返回、自有打算、共同材料及工具失败：

```powershell
python utils/compare_dialogue_expression.py
```

默认只准备上下文，不调用模型。显式 `--real-model` 最多选两个情境，新旧各一次，使用相同模型、参数和历史、交替调用顺序，不读取真实聊天、不生成 TTS：

```powershell
python utils/compare_dialogue_expression.py --real-model --case teasing --case disagreement
```

本轮共完成 6 次合成模型生成：两组初始对照，以及发现问题后重查一组。另一次请求在 TLS 握手阶段超时，随后一次有界重试成功。初始新版本虽然更愿意展开，也凭空补出一段观鸟往事；补充事实边界后的重查样例没有再出现具体过去经历。旧版本在分歧情境中也能自然坚持自己的兴趣，新版本并非所有样例都更好。

这些是少量随机抽查，提供的感受与意图为合成值，不代表已经验证真实状态生成质量，也未完成盲测或长期陪伴评估。新版本可能更长、细节更多，是否更合口味需要实际使用反馈。不能用测试通过代替对活人感的评价。

## 回退

`DIALOGUE_POLICY=legacy` 读取原始 YAML 并停用当前视角注入，恢复旧关键词反馈处理；只切换表达层，不删除新字段与记忆。本机重启后生效。容器修改 `deploy/service.env` 后执行：

```powershell
docker compose --env-file deploy/service.env -f compose.service.yml up -d --no-deps --no-build --wait --wait-timeout 240 ember
```

更新前另保留应用镜像 `ember-service:before-expression-v1-20261107`，可将 `EMBER_SERVICE_IMAGE` 临时指向该标签并执行上述命令，回到更新前完整应用版本。任何回退均不删除数据库或运行数据卷。

本轮已实际更新本机容器。新旧表达版本均在无网络、只读临时容器中通过加载检查；更新前两次确认业务空闲，更新后 `/config` 显示 `expressive_v1` 与 9 处适配，应用、数据库、长期记忆和场景就绪。更新前已有 **39 条**聊天内容哈希全部一致，运行卷的人设 YAML 哈希保持不变，手机尺寸页面检查通过。诊断未发送真实消息或保存真实场景，临时验证登录已注销，测试数据库已停止。
