# 三层记忆衔接修复

日期：2026-11-02。对应[修复前检查](memory-audit-2026-11.md)。本次补齐召回结果回填、中期工作记忆与可靠整理触发，保留现有数据库和历史记录，不自动重编码全部旧记忆。

## 现在的流程

```text
带时间与消息ID的对话
  ├─ 短期窗口（默认20条消息）→ 正常交谈轮次
  ├─ 移出窗口前 → 持久中期缓冲（最多80条）
  │                 └─ 有原文来源的话题、问题、决定、意图、偏好（最多32条）
  └─ 结构化经验日志
        → 窗口压力 / 累计消息 / 周期 / 明确记忆请求 / 活动结束 / 空闲模型建议
        → 编码为长期记忆＋带引用的中期事项
        → 持久写入待办 → 向量生成 → 数据库提交回执
        → 确认整批成功后消费对应日志前缀

模型请求记忆工具
  → 向量与关键词检索、可选图谱查询
  → 多条记忆正文＋时间来源＋置信度＋消息证据＋图谱内容
  → 状态模型 / 对话模型再次调用并消费结果
```

短期20条通常约10轮，不等于20轮。前端完整历史仍独立存储，不会每轮全部发给模型。

## 召回内容

给模型的内容与界面/日志的短预览已经分开。模型不再只获得第一条记忆前60个字符。选中的多条记忆、图谱实体描述和关系通过结构化数据回填，包含原始时间、置信度、来源消息与原文证据。

单次工具回填设约32000字符预算。超出时跳过整条记录并显示 omitted 数量，避免悄悄截掉事实末尾；不是无限注入整个记忆库。图谱本身仍使用既有检索与相关片段选择。

查询失败返回失败信息。查询向量不可用但关键词查询可用时，明确标记“仅使用关键词”，同时传给模型并显示在设置中，不将降级隐藏成完整语义检索成功。

实际工具格式 `<tool>` 与兼容的 `<tool_call>` 均从流式对白中隐藏；中断的工具调用不作为助手对白保存。

## 中期工作记忆

新增 `config/working_memory.json`，包含原文缓冲、带引用的事项和未完成整理待办。短期消息移出窗口前，必须先原子保存到中期缓冲；保存失败不能静默淘汰。

编码模型只能为事项选择类型并引用原文：topic、question、decision、intention、preference。引用必须逐字属于真实消息；解决情况需附回应消息与原文。程序校验引用，拒绝凭空生成的来源。分类仍可能不准确，因此 mentioned 仅代表提及，不能视为事实、有效承诺或已经执行的动作。

回复上下文优先注入近期有来源事项，再补原文缓冲；有约9000字符预算，并标注截断与时间。即使模型整理失败，原文缓冲仍可承接最近移出窗口的对话。中期层有容量上限，完整消息仍在历史数据库与未消费日志中。

原始消息有毫秒时间戳和稳定ID；日志中区分用户自述、助手发言、角色状态推演与玩家界面活动记录。计时完成只证明玩家提交了记录，不证明现实学习成果。未知时间不填成编码当日：长期记忆的 time_basis 标记来源消息时间、模型估计或未知。来源消息时间不是约定目标时间。

## 整理触发与成本

默认行为（无需修改现有业务 `.env`，新字段可覆盖）：

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `MEMORY_ENCODE_MESSAGES` | 12 | 日志累计消息达到阈值 |
| `MEMORY_ENCODE_INTERVAL` | 120 | 有新对话时的周期检查间隔，现实秒 |
| `MEMORY_RETRY_INTERVAL` | 60 | 自动整理与失败重试的最小间隔，现实秒 |

窗口压力、明确“请记住/别忘了”等输入、完成/中断活动也可要求整理。整理在心跳检查点、当前对话完成后进行，服从暂停世界、存读档与串行操作锁。仍可接受状态模型的空闲整理建议，但不再仅依赖它。

每次编码同时产生长期摘要与中期事项，没有为每一条消息额外增加一轮模型调用。比原先长期不整理的路径会增加编码和向量调用。整理占用当前世界操作锁，模型较慢时，下一轮对话可能等待当前整理完成；这不是独立分布式任务系统。

每次向量写入最多尝试3次，失败保留资料；之后按自动重试间隔再调度。长时间服务故障时会持续保留并重试，可通过暂停世界暂停新调度。尚未加入每日费用配额。

## 数据保护与恢复

- 编码后的待办先写入中期文件，再交给向量存储；订阅方需要返回已可靠接收的回执。
- 日志直到数据库提交回执到齐才消费。消费前保存提交意图，重启能处理“尚未消费”和“已消费但待办未清理”两个崩溃窗口，不删除后来追加的日志。
- 批次、记忆与消息均使用稳定标识，重试沿用原记录，数据库按 memory_id 去重。
- 首次升级可接管已有失败向量待办，不删除它们。
- 中期文件和待办随游戏存档导出；导入失败回滚也恢复它们。旧档没有此文件时恢复为空，不能携带当前分支的中期内容进入旧档。
- 读档后，不属于该档案的失败向量文件移至 `data/failed_memories/retired/`，保留但不自动重放。当前分支需要的待办可从中期文件重新投递。
- 没有迁移或清空业务表，没有重写已有长期记忆内容。新来源信息使用既有 metadata JSONB。

## 限制与回退

记忆分类、摘要与检索选择仍可能出错，不保证模型每次都主动调用工具或完全遵从来源。现有图谱整理与遗忘规则没有整体重做，也未对过去记录补齐不存在的证据。

回退前先停止后端，备份完整配置、日志、失败待办和数据库。尽量等“待入库”为0后回退本次程序文件；待办未完成时优先保留新逻辑排障，避免旧后台以另一套编码规则重复整理。不要使用清空记忆或删除数据卷作为回退。中期文件可保留备份，不应随意删除；本次没有新的关系表迁移需要撤销。
