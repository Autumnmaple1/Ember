# 对话重整交付与使用说明

日期：2026-11-08。对应[对话约束重整规划](dialogue-policy-redesign.md)四个阶段的工程实现、回归和有限模型评阅。第一阶段详见[表达层记录](dialogue-expression-phase1.md)。没有扩展 Android／Windows 同步、多人格或完整地理模拟。

## 交付范围

| 阶段 | 实际交付 |
|---|---|
| 表达自由 | 版本化表达偏好、精确兼容旧默认句、无关键词固定回应、简短当前视角、自定义人设原文保留 |
| 持续状态 | 按消息标识处理情绪、按世界时间衰减、睡眠转换、候选意图与主观猜想分离；一种角色自有活动及持久事件 |
| 主动节奏 | 从真实提交的记录产生投递机会，事件标识去重、话题间隔、现实时间滚动预算、可检查的未发原因、明确开启的网页提醒 |
| 验证与评阅 | 隔离自动回归、12 组匿名对照材料、三轮真实状态到回复流程及针对问题的复查；不把它们当成用户盲测或长期效果证明 |

## 情绪的持续性

`role_continuity` 存在角色状态 JSON 中，模型不能覆写。真实接收的用户消息以稳定标识为依据，同一条输入的情绪影响只处理一次；角色规则事件和睡眠转换也可形成新的起因。可以不快、犹豫、委屈和不同意，不要求每轮恢复温柔。

没有新起因时，PAD 以事件发生时的值为起点，向该角色的既有基线缓和，默认半衰期 3600 个世界秒。计算取决于经过的时间，不依赖调用了多少次心跳。重复回看同一句反馈不能继续降低数值、重置起点或叠加伤害。

感受作为主观记录保留；余韵很淡时不再作为当前感受反复注入，原始记录不删除。睡眠有独立的低唤醒目标，睡眠状态随存档恢复。`STATE_UPDATE_INTERVAL` 仍控制模型更新 PAD 的轮次；规则按时间产生的自然变化独立运行。

候选意图、关注点、角色猜想与已发生事件分别表达。`beliefs` 标记为 `role_interpretation`，不能当作用户真实想法。旧状态没有新字段时正常加载，在后续有效状态更新中逐步建立记录。

## 角色自己的活动

首个活动是“整理自己的笔记”，只属于角色。模型可以提议开始、暂停、继续或提前结束；程序只接受已支持的种类，在已知角色地点开始，默认一轮 900 个世界秒、每天最多开始两轮。

程序推进开始、中段、结束；暂停不累计时间，换地点立即中断，在同一地点才可继续。模型输出“已完成”不能直接改变活动结果。计时阶段也不证明完成了半页、整页或获得任何具体知识。

每个事件有稳定标识、世界时刻、角色地点和来源，参与者固定为角色。离线推进明确标为 `offline_simulation`，不会补成用户共同活动，也不当作刚发生的新消息推送。读档恢复活动和时钟，现实投递账本不随游戏读档倒退。

加速世界后正常启动若现实时间早于存储活动，则保留旧分支，暂停活动并重新计算当前进度；未来记录不作为当前既往经历展示或投递。继续活动使用新的分支标识，避免旧未来事件挡住当前分支的进展。显式读档仍按存档世界时钟恢复。

用户可在“回忆 → 活动回顾”的“她的近况 · 虚构世界”查看这些记录。它与用户手动操作的自习记录分开。活动是否开始由角色状态模型的候选行动决定，不承诺每次打开网页都有新故事。

事件先保存为状态中的记忆待办，再进入原始日志和工作记忆；写入失败保留待办并重试，不丢弃尚未导出的旧事件。编码、向量入库及召回保留 `role_simulation_record` 来源，正文附带虚构世界标记，不能变成用户经历。已有聊天和记忆没有被整体重写或清空。

## 主动发言与提醒

投递机会只取自已提交记录，模型不能自己声明“重要”以突破限制。

| 机会 | 来源与条件 | 默认节奏 |
|---|---|---|
| 普通续聊 | 最近一条真实用户消息；模型还需判断有内容可说 | 普通间隔 600 现实秒；同一话题机会只尝试一次 |
| 角色近况 | 近期在线完成的角色自有活动 | 与普通事件至少间隔 120 现实秒；用户未回应时先留待回来再谈 |
| 共同自习计时 | 用户明确开启的共同计时达到目标 | 可独立提醒一次；不声称用户已完成作业 |
| 网页提醒 | 用户核对确认约定后，另行指定明确时间并开启 | 独立于闲聊未回应限制，默认至少间隔 30 现实秒，每现实小时最多 6 次 |

普通续聊、角色近况和共同活动合计每现实小时默认最多 3 次；同一程序话题标识另有 30 分钟现实间隔。普通续聊按最后用户消息区分机会，角色活动按活动标识合并，不依赖模型自己标记“重要”。提醒不依靠模型再生成正文，沿用原有稳定消息标识、保存、WebSocket 和 TTS 路径。

所有类型都遵守勿扰设置、睡眠、世界暂停、存读档和用户输入优先；没有网页连接时不投递。普通主动消息未获回应时，不连续自我剖析；明确开启的提醒及共同计时可以单独处理。模型无话可说时允许静默，仍结束并释放轮次。

事件在生成前写入现实投递账本。重启、读档、重连、模型失败和回执不确定均不盲目重发同一事件。账本记录 `reserved/delivered/silent/failed/interrupted`；`delivered` 表示保存并进入消息流程，不表示用户读过或听过。损坏账本保留原文件并停止主动投递，不静默清零。

`/config/status.proactive` 提供最近判断、投递记录、预算及错误，设置面板显示简短原因。模型在空闲演化中没有内容的决定另记为 `last_evolution=no_content`，不伪装成系统故障，也不将这些诊断念进对白。

### 开启网页提醒

1. 在回忆中找到有来源的对话，记录约定并核对确认。
2. 在该约定卡片填写“网页提醒时间（世界时间）”，点击“开启网页提醒”。
3. 可单独关闭；将约定取消、完成或改回待确认也会关闭提醒。

这里仅支持明确的日历日期和时间，按后端世界时钟和 `TIMEZONE` 解释；加速世界也会加速到期。聊天工具目前不含创建提醒，角色说愿意帮忙不等于已经建好任务。UI 会显示等待、已发送、失败待核对或错过等状态；保存失败保留填写内容并在按钮附近显示原因。

提醒受勿扰、睡眠、连接和预算影响，到期后超过十五个世界分钟不补发。服务停止期间不会运行，不发送手机系统通知，不写入手机闹钟。离线期间的事件保留为回看材料，不在重连后集中刷屏。

## 配置与规则归属

本机改 `.env`，容器改 `deploy/service.env`，重启相应后端生效：

```dotenv
DIALOGUE_POLICY=expressive_v1
ROLE_CONTINUITY_ENABLED=true
ROLE_EMOTION_HALF_LIFE=3600
ROLE_ACTIVITY_SECONDS=900
PROACTIVE_POLICY=events_v1
PROACTIVE_MIN_INTERVAL=600
PROACTIVE_EVENT_GAP=120
PROACTIVE_HOURLY_LIMIT=3
```

表达风格继续用 `dialogue_style` 管理。600 秒只用于普通续聊，不再是所有事件的统一间隔。默认值是低打扰的暂定选择，尚未用用户长期偏好证明为最优。

| 规则 | 唯一权威或主要入口 |
|---|---|
| 人设及作者表达偏好 | 原始 YAML 与 `config/dialogue_policy.py` 的内存适配 |
| 时间、结构化场景 | 后端时钟、`persona/scene.py`；模型不能改时钟 |
| 主观感受与候选意图 | `persona/reply_view.py`；不自动成为事实 |
| 情绪事件与角色活动 | `persona/continuity.py`；状态提交后才广播 |
| 原始轮次与历史时间 | `brain/dialogue_context.py`；不把历史压成伪用户任务 |
| 记忆来源 | 原始消息、工作记忆与编码校验；虚构、对白及用户自述区分 |
| 是否投递 | `core/companionship.py` 与 `core/proactive_events.py`；来源、预算、去重由程序决定 |
| 生成和消息保存 | `brain/core.py`；正文与思考内容保持隔离 |

状态模型与回复模型各自获得相关边界。状态模型只读取紧凑的连续性摘要，不读取全部去重标识和记忆待办账本；避免每轮上下文随内部记录无限增大。旧 YAML 的已知风格与主动模板句可通过 `utils/preview_dialogue_policy.py` 预览有效差异，不会覆盖自定义人设文件。

## 更新与回退

本机使用 `start_service.bat` 正常构建更新。更新前等待当前任务结束，保留应用镜像和世界恢复点，仅更新应用服务，不重建数据库或数据卷。

优先按层回退，在容器 `deploy/service.env` 选择：

```dotenv
DIALOGUE_POLICY=legacy
ROLE_CONTINUITY_ENABLED=false
PROACTIVE_POLICY=legacy
```

再执行：

```powershell
docker compose --env-file deploy/service.env -f compose.service.yml up -d --no-deps --no-build --wait --wait-timeout 240 ember
```

这会保留新记录，但停用新表达层、连续性演化与事件投递。统一节流回退也保留既有事件去重账本，重新开启新策略不会忘掉已经尝试过的事件。

整体应用回退镜像标签为 `ember-service:before-dialogue-final-20261108`：临时设置 `EMBER_SERVICE_IMAGE` 为该标签，再执行同一命令；结束后 `Remove-Item Env:EMBER_SERVICE_IMAGE`。需要回到发布前的世界内容时，在存档页选择 `before-dialogue-final-20261108-` 开头的恢复点。读档会恢复存档时间，正常启动仍跟随现实时间。任何回退都不删除卷。

本轮已完成本机发布：恢复点为 `before-dialogue-final-20261108-gfkml6`，更新后应用健康，数据库、长期记忆及场景就绪；`expressive_v1`、`events_v1`、连续性和网页提醒能力均已启用。原有 **39 条**聊天逐条内容哈希一致，运行卷的人设 YAML 原文哈希不变，真实手机尺寸页面已显示“她的近况”。核验没有发送聊天或保存真实场景，临时诊断登录已注销，独立测试数据库已停止。
