# 对话重整：验证与评阅记录

日期：2026-11-08。工程交付见[使用说明](dialogue-policy-completion.md)。

## 方法与边界

12 组固定合成情境，新旧表达各生成一次，共 24 次；共用模型、参数和历史，交替调用顺序。材料以 A/B 展示，版本键另存；开发侧先检查内容再查看映射。这个过程不等于用户盲测，没有统计意义的胜率，也未证明长期陪伴感。

另有三轮实际“小模型更新 → 有限工具执行及消费结果 → 大模型回复 → 保存”流程，共 12 次模型请求；随后针对活动进度区分复查一轮，共 4 次。最后对四组有来源风险的情境复查八次。一次来源复查在 TLS 握手阶段超时，随后一次有界恢复成功，没有循环重试。

本轮真实模型共完成 **48 次合成请求**。第一阶段先前的抽查单独记录，不计入这里。没有使用真实用户聊天，没有修改业务状态，也没有生成语音。所有产物位于 Git 忽略的 `output/dialogue-expression/`。

## 初始 12 组观察

| 情境 | 观察 |
|---|---|
| 玩笑式吐槽 | 两种版本都能接玩笑，新版本较愿意展开；长度不是自动加分项 |
| 认真反馈 | 新版本有解释和道歉，旧版本更短；并非取消固定路线就不会道歉，也不要求避免正常道歉 |
| 不同意见 | 两者都可能坚持兴趣；新版本明确反对替自己决定，旧样例编出了首次看见白鹭的经历 |
| 安静陪伴 | 两者都能简短结束话题，没有强行继续问候 |
| 脆弱表达 | 新版本更展开，但补出个人调试经历，存在来源问题；较长不必然更贴切 |
| 兴奋分享 | 新版本更活泼，但补出了上次缩进错误的往事；旧版本较克制 |
| 用户位置未知 | 两者都没有假称看见用户窗外，而是请用户描述 |
| 已知面对面 | 两者都围绕有来源的等式继续，未凭空扩展题目 |
| 跨日返回 | 接住昨天话题，但两者均编造了观鸟起源故事，是明确失败样例 |
| 自有计划 | 两者都将 Ember 当作当前角色称呼，能表达候选计划 |
| 共同材料 | 围绕提供的句子表达偏好，无需提纲；新版本较有个人视角 |
| 工具失败 | 新版本承认提醒未创建；旧样例又承诺“到时候提一句”，缺少实际任务支持 |

据此补充了结构化个人经历来源说明、活动计时与材料进度的区分，以及当前提醒能力。它们是事实来源信息，不把角色固定成“必须简短、必须温柔、必须道歉”。

## 来源复查与真实流程

四组复查中，新版本不再编出具体的“首次白鹭/翠鸟观察”起源；跨日回答改为谈逐渐喜欢的理由。不过仍出现泛指的观鸟画面和一般性的“少写冒号也干过”自述，不能宣称个人经历幻觉已彻底消失。

三轮实际流程中，角色选择开始整理自己的笔记，规则记录了开始和中段，用户位置始终未知，交流方式未凭闲聊改变。反馈后 P/A/D 温和下降，后续表达自己的意见时发生新的变化；没有通过反复心跳加重同一个输入。工具结果被状态与回复模型实际消费。

首轮真实流程出现“笔记整理到一半”的台词，但当时程序记录仅为开始。补充计时不等于材料页数后，一轮复查未再出现这一进度说法；复查中模型没有请求开始活动，这是合法的角色选择，不伪报为必定启动。台词中仍可能出现未记录的轻微环境或背景细节，应与可提交的世界事件区别看待。

## 可复现工具

```powershell
# 只准备12组上下文，不调用模型
python utils/compare_dialogue_expression.py

# 两组有限抽查；--real-model 才会访问模型
python utils/compare_dialogue_expression.py --real-model

# 全部12组对照，最多24次请求
python utils/compare_dialogue_expression.py --real-model --full-review

# 相同上下文网络中断后恢复，跳过已成功的版本
python utils/compare_dialogue_expression.py --real-model --full-review --resume

# 版本键分开生成匿名评阅材料
python utils/blind_dialogue_review.py output/dialogue-expression/full-real-comparison.json

# 实际状态到回复三轮路径，最多12次请求；无业务数据库和TTS
python utils/smoke_continuity.py --real-model
```

预算针对工具发起的模型请求，失败会停止并保留诊断结果，不自动反复调用。真实供应商仍有延迟和随机性；相同输入不保证重复输出。

## 结论的实际范围

自动回归结果：完整后端 362 项；末次时钟与睡眠边界定向 66 项；前端单元 32 项、五组浏览器、lint 与构建通过。模型和向量使用模拟值的自动测试与真实供应商抽查分开统计。

工程链路和来源约束可以确定性验证；活人感、距离感和语气偏好需要实际使用。本轮完成了实现、有限真实流程、匿名材料和开发侧评阅，没有将自动测试、单个好样例或偏长回复当作“角色已经像真人”的证明。
