## 结论

短期窗口确实在使用；长期记忆有编码、向量存储与召回访问证据。没有独立完整的中期记忆层。长期结果回填存在明确的信息丢失，不能将“库里有记录”当作“模型已获得足够记忆”。

## 实际流程

### 短期

`Brain` 接受输入 → `ShortTermMemory.add_message` → 保存带时间戳消息到 `config/chat_memory.json` → 下一轮通过 `get_full_messages` 获取 → 正常 user/assistant 轮次进入模型。

当前配置 `CONTEXT_WINDOW_SIZE=20`，计数单位是消息，不是往返轮次；通常约 10 轮。超出窗口直接截去最早消息，完整历史仍由 `DBMemory` 独立保存。前端能翻看 166 条历史，不意味着模型每次能看到全部 166 条。

### 中期

没有独立的中期缓冲区、稳定的话题摘要、未解决事项集合或从短期淘汰到中期的流程。`StateManager` 的“近期综合轨迹”“近期目标”会持久化和注入回复，可提供部分连续性，但它们是模型不断改写的短文本。

共同手册的当前状态、卡片和选择也会注入对话；它是特定活动状态，不等于覆盖所有话题的中期记忆。玩家收藏和约定同样不能直接视为已被角色长期记住。

### 长期编码

短期消息与状态记录写入 `chat_history.log` → 空闲演化返回 `action_pulse.memory_encode=true` → 发布 `memory.preprocess` → `Hippocampus` 调模型提炼 → 发布 `memory.store` → 先保存待处理文件 → `EpisodicMemory` 生成两份向量并写 PostgreSQL → 成功后删除待处理文件。

触发主要来自空闲演化，不是在每次答复结束或窗口即将溢出时确定执行。持续聊天、频繁重置空闲计时或模型一直不要求编码时，长期整理会滞后。

睡眠转换触发 `memory.sleep`，执行情景记忆清晰度衰减、低清晰度删除及可选图谱整理。睡眠整理也不是中期记忆层。

### 长期召回

状态模型或对话模型选择 `memory_query` 工具 → `Hippocampus.query_memory` → 情景向量/关键词检索与图谱查询 → 格式化工具结果 → 再调用模型消费结果。

旧的 `Hippocampus.load_memory` 接口还存在，但当前正常对话没有直接调用它。正常路径依赖模型选择工具，不保证每轮主动唤起与当前事项有关的记忆。

## 已确认的回填问题

`ToolCallProcessor.format_tool_results_for_prompt` 调用 `MemoryQueryTool.summarize_result`，后者只返回“找到 N 条记忆”、第一条约 60 字符预览和最多几个实体名。模型没有收到其余情景记忆、图谱属性及关系内容。

合成复现输入三条记忆，将关键结论放在第一条末尾与第二、第三条，并加入实体偏好和一条关系。实际模型回填只包含第一条前缀与实体名，五项关键结论/属性/关系均未进入回填。复现不连接数据库或模型。

这是代码层面的信息丢失；即便向量检索成功，也可能表现为角色仍想不起关键事实。原先“状态模型会消费工具结果”的流程已接通，但消费到的内容过于简略。

## 其他衔接风险

- 消息在短期 JSON 中有时间，但编码日志里的 user/assistant 行没有逐条附带时间、稳定消息标识和来源。日志混合角色状态与推演，长期编码较难严格还原每件事的证据。
- `_simplify_memories` 将时间压为日期，只保留内容；置信度、记忆 ID 与更细时间没有一起交给模型，不利于核对与纠错。
- 空闲编码与工具召回都依赖模型判断，缺少可靠的淘汰前整理及重要事实兜底。
- 向量查询按相似度取前 K 条，没有显式相关性门槛；命中不必然相关。
- 部分查询失败返回空结果，会混淆“没有相关记忆”和“查询故障”。`/config` 的长期 ready 也不代表所有编码、图谱、召回、回填环节均成功。
- 编码日志清除依赖事件订阅方已成功保存待办，但事件总线会捕获订阅异常；若保存待办失败，发布方没有成功回执可核对。这是错误场景下的潜在丢失路径，本次未在业务数据中触发。

8 条长期摘要与 166 条原始消息数量不同本身不能证明丢失；摘要压缩、遗忘、导入恢复都会影响数量。

## 建议修复顺序

1. 把真正的记忆内容、来源、时间与置信度回填给模型，单独保留用于界面/日志的简短摘要，并增加跨多条结果的有效信息测试。
2. 增加可检查的整理触发：窗口淘汰前、重要事实确认后、活动结束及周期检查；写入失败保留可恢复待办并有完成回执。
3. 建立中期工作记忆：当前话题、共同关注对象、未回答问题、已达成决定与未完成意图；独立于不断改写的角色情绪状态。
4. 补齐来源、事实/推演区分、时间有效性和召回故障状态，再完善图谱关系整理。

本次是检查报告，以上修复尚未实施。没有清空、重编码或重新整理现有业务记忆。
