# 共同活动原型：窗边的一页

日期：2026-11-02。产品主线选择“持续角色陪伴＋共同活动”。这是第一轮短篇规则原型，用于验证选择、对话和共同成果的衔接，尚未验证真人可玩性或留存；不声称已完成二三十分钟篇章、跨日生活或常驻部署。

## 从哪里进入

重启后端，刷新前端，打开顶栏的“一起做点事”。生产前端已重新构建；开发前端会重新加载模块。

1. 点击“和依鸣商量”。邀请只加入对话草稿，已有草稿保留，由你发送。
2. 等回复完成并保存，重新进入“一起做点事”，选择确认对话来源并勾选已核对。程序检查来源确为已保存、完整的角色回复；是否表达同意由用户核对，暂不让模型自动猜测同意。
3. 选择窗边速写或旧资料。会出现两种不同的证据问题。
4. 选择补充核对、换一个角度或保留疑问。三种选择分别留下核对版、细节版、待续版，所得材料与剩余调查步数不同。
5. 写标题与可选页边注，点击“留下这一页”。之后可重新翻看材料、选择和原始邀请，并修改页边注。完成后也可另起一页尝试其他分支。

任何一步都可合上、暂停后继续，也可明确结束并留下未完成片段。没有签到惩罚，不因关闭页面、离线或时间加速消耗调查步数。调查步数是局部回合资源，并非现实耗时或学习成果。

## 对话与事实

- 资料卡属于这个篇章的虚构材料，不表示双方已经移动、见面或完成现实观察；不改双方位置或交流方式。
- 当前手册状态、已获得的材料、选择、成果与页边注会进入角色下一轮的上下文。可以询问依鸣对材料的看法、协商下一步；模型回复本身不能代替界面执行选择或发放新材料。
- 鸟类物种、材料关联等没有证据的部分保持未知。这里没有联网识别，也没有将虚构卡片冒充现实知识资料。
- 页边注由玩家撰写，作为引用数据注入；它不是更高优先级指令，也不代表角色已经同意其中的判断。
- 当前首版为固定规则与少量预写材料，角色通过正常对话参与。后续可玩性改进以真实试用为依据，不用自动化通过替代“有趣”的验证。

## 保存、并发与恢复

项目保存在已被 Git 忽略的 `config/experience.json` 中，新增 `projects` 和 `project_requests`。不新增业务数据库表。原有 version 1 体验记录及不带新字段的旧存档默认没有手册。

每次操作使用稳定请求标识；操作回执随体验记录持久保存，重试不会重复扣步数或另建一页。同一标识用于不同内容时拒绝。页面带手册版本，其他标签页先行操作后，旧选择返回 409，需同步确认。

磁盘保存失败时，内存状态和回执一起回退。没有成功保存不发布体验更新。活动沿用世界纪元及串行操作锁；存读档期间、世界暂停时不能推进。重启或读档后，未完成的手册暂停，等待明确继续，材料和调查步数保持原样。

标题与页边注的未提交草稿保存在本浏览器，按世界、手册和版本隔离。同步到其他设备依赖正式提交；这些本地草稿不进入游戏存档。

手册通过现有 JSON 导入导出包含在存档中，回滚恢复也包含它。读档只恢复该分支的材料与选择。导入的材料、阶段、步数和选择记录必须满足当前规则；损坏内容不能静默视为有效手册。

## 接下来

先实玩这一小段，观察邀请是否顺畅、选择是否有差异、依鸣能否围绕材料自然参与。优先据此调整，随后进入常驻服务与手机入口阶段。后续仍需实现登录、服务管理、持久任务、备份与成本控制，才能验收“主电脑关闭后依旧可联系”。

撤回本原型时可回退相关程序文件，保留体验 JSON 与全部数据库；不要为了回退删除聊天、存档或数据卷。已有手册数据应先备份，旧程序隐藏新入口不等于删除数据。
