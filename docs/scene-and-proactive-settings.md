# 场景直接保存与网页主动陪伴

2026-11-07。

## 使用方式

打开“查看当前情境”，填写位置与故事中的交流方式，点击“保存场景”。成功后立即更新当前状态，不再生成确认草稿，也不会自动发消息、调用模型或语音。正在编辑的聊天草稿保持原样。

未知位置可以留空；面对面要求双方位置已知且相同。故事中的远程交流仍需确认相应联系方式，这不代表程序已经接通微信或电话。日常对话里的“我到了图书馆”等明确表达仍可经过原有场景识别更新。

若后台场景在填写过程中改变，保存会提示冲突并保留表单。点击“载入最新场景并替换表单”后重新核对。文件保存失败、对话处理中或存读档期间会明确报错，不显示虚假的保存成功。

设置里新增“主动陪伴 → 允许网页内主动发言”。它与专注视图的“勿扰 · 暂停主动发言”控制同一个偏好：允许开启等于勿扰关闭。偏好保存在后端，刷新可恢复；普通游戏读档保留当前偏好，不把它回退到旧存档值。保存失败会恢复已确认的开关值。

网页主动发言不再要求知道用户位置、面对面，或在故事里交换微信/电话。位置未知只限制共同空间、触碰和递送物品的描写。角色仍须有具体内容才主动开口，并遵守睡眠、勿扰、世界暂停、存读档与用户消息优先等规则。

主动消息目前只在 Ember 内保存、显示；声音由“自动声音”单独控制，没有新增外部消息平台或手机推送。

## 实现与来源

- `POST /scene` 接收世界 epoch、表单打开时的场景及新场景。只允许四个结构化场景字段，拒绝时间、PAD 等额外字段；系统时钟仍是唯一时间来源。
- 后端在世界操作锁下检查当前场景，避免覆盖对话、心跳或读档后的新状态。比较场景事实本身，普通情绪更新不会使表单失效。
- 手动确认写入 `state_source=user_ui` 与包含服务器时间、唯一标识、场景快照的 `scene_confirmation`。这份来源不能由模型伪造。沿用状态文件提交、状态持久化与广播流程，不写入虚假的用户/AI 聊天消息。
- 手动确认会刷新位置的有效时间，但不改写上一条用户消息时间；重启与读档可以恢复这份确认。位置仍会随长间隔失效，这不再禁止网页渠道的主动发言。
- HTTP 身份验证和 CSRF 保护沿用现有中间件。接口不绕过场景一致性校验，也不允许前端设置后端时钟或人物情绪。
- 后端为网页渠道向状态模型和回复模型补充渠道说明，覆盖旧模板中“必须先有微信/电话才能联系”的歧义。未知场景的物理行为约束保留，卷内自定义人设没有被覆盖。
