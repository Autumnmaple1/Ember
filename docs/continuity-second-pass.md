# 共同注意与返回衔接 第二轮

日期：2026-11-03。接续“持续角色陪伴＋共同活动”路线与角色在场感诊断。本轮完成一个明确片段：围绕同一段真实提供的文字讨论，离开后返回仍能找到它，并且不把上次位置当作当前位置。

## 现在可以怎样用

1. 在聊天中发送题目、代码或文字，等待“已保存”。点击该条用户消息下的“一起看这段”。
2. 为材料起名，选取原消息中的一段文字并确认。最多 6000 字，必须逐字属于来源，不能在此补写原文以外的条件。
3. 通过世界栏的“接着上次”找回当前材料、手册、自习和已确认约定。点“围绕这段继续聊”填入草稿，由你发送；已有草稿保留。
4. 可以查看材料来源、先收起或重新选为当前材料。收起保留记录，当前上下文不再把它当作正在一起看的材料；这不等于删除旧聊天。
5. 未完成的手册可以继续，已完成的一页可以回看和修订。打开入口不会替你继续计时、推进步骤或确认新约定。

代码生效需重启原来的 `server.py` 后端并刷新前端。前端生产构建已完成；开发前端仍使用原来的启动方式。本轮没有替换已交付的中期 ZIP，修复版中期包保持原有提交内容。

## 为什么这样处理

此前的中期工作记忆保留原文和摘要，但没有一个明确的“本次一起看的对象”。现在共同材料由用户从已保存消息中选择，带稳定来源，直接进入回复前状态模型和对白模型上下文；短期窗口淘汰原消息后，当前材料仍然可用。来源时间由后端换算为带时区的可读时间，旧约定缺少正文或时间时保持未知。此路径没有新增模型调用阶段。

引用的内容以数据呈现，不覆盖系统规则。没有提供的页、图、代码和题目条件仍保持未知；共享文字不意味着同处一地。已确认的约定也进入有界上下文，但用户确认的是一条记录，不自动代表角色承诺、事情完成或今天到期。

## 时空修正

原有 `last_interaction_logical_time` 同时承担空闲演化计时，每次空闲更新都会重置。它无法可靠表示距离上一次用户交谈多久。新增单独的 `last_dialogue_logical_time`，空闲模型不能刷新它，启动和读档从带时间的短期用户消息恢复。

- 间隔达到 30 分钟世界时间，旧用户位置和面对面/远程状态失效。
- 跨日期且间隔达到 5 分钟时，同样不把上次位置作为当前事实；午夜连续短聊不会仅因日期变更而清空位置。
- 保留角色位置和已经确认的联系方式，旧用户位置只进入 `last_known_presence`，不能自动回填。
- 用户明确说明返回、地点或交流方式后，仍走现有原文证据校验重新确认。不因位置未知而要求重新认识，也不每轮盘问。
- `/config` 提供只读的当前视图；实际状态在对话或空闲处理前保存，再广播。世界加速影响此规则，因为它判断的是虚构世界的连续性。

这是一层基于交谈间隔的保守规则，不是 GPS 定位、完整地理模拟或每个地点字段独立的证据时效系统。角色活动连续性与跨日内容量仍需后续迭代。

## 数据与恢复

材料保存在现有 `config/experience.json` 的可选 `materials` 字段，不新增数据库表。旧 version 1 体验文件默认材料为空。每份保留标题、原文、用户消息来源和当前/收起状态；同一来源同一段文字重复确认不会重复创建。切换聚焦、记录与落盘一起回退，失败不广播成功。

新材料沿用真实存档的 JSON 导出、导入与回滚。导入校验原文归属、来源角色及唯一聚焦；破损记录返回失败。HTTP 操作受世界纪元和串行锁保护；旧分支请求被拒绝。前端将接续内容与体验记录的版本一起合并，迟到快照不能单独覆盖新入口。

回退前先等待当前任务结束、关闭后端，备份体验 JSON 和存档，再恢复前后端代码。保留全部数据库卷与材料文件；旧界面没有入口不代表材料已删除。
