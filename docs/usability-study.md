# Ember 可用性走查与真人研究记录表

适用版本：2026-11-02 的交互改造。此文件是待执行的研究工具，不包含虚构参与者或预填成功结果。

## 执行方式

先在合成数据和独立测试存档中走查。正式研究建议 5–8 位参与者，覆盖经常聊天、熟悉视觉小说/陪伴游戏和较少接触此类产品的用户。由项目负责人取得参与同意，说明是否记录屏幕、记录用途及删除方式；不默认采集私人聊天。

每位参与者使用匿名编号。主持人只说任务目标，不提示按钮位置。遇到失败先记录，再决定是否继续，不把受指导完成记作独立成功。允许随时停止。

## 任务卡

| 编号 | 交给参与者的目标 | 观察重点 |
|---|---|---|
| T1 | 发一条含中文选字与换行的消息 | 选字不会误发；能理解接收与保存反馈 |
| T2 | 找到某天含指定关键词的对话，并确认上下文 | 搜索、日期、分页、定位后阅读不被新消息拉走 |
| T3 | 关闭自动声音后接收回复，再单独重播一句 | 文字保留、静音可信、声音与生成语义分离 |
| T4 | 暂停正在播放的声音，再继续播放 | 不误停止模型，不重新播放旧队列 |
| T5 | 打断一条长回复，发送新的问题 | 等待真实停止；草稿、待发与中断片段可理解 |
| T6 | 说明目前双方在哪里、如何交流，并更正一个未知字段 | 不从背景推断用户位置；确认草稿不是即时世界修改 |
| T7 | 开始个人自习，暂停后结束并记录一段实际回顾 | 计时与世界倍率分离；不误以为角色已加入 |
| T8 | 从已确认对话开始共同自习 | 理解来源和主动确认；不靠勾选制造未发生经历 |
| T9 | 收藏一句话，整理一个日期未知的约定，再找到来源 | 收藏/模型记忆/推演区别清楚；未知时间不被自动补全 |
| T10 | 保存当前状态，发生一些变化，再恢复存档 | 预览、自动备份、真实阶段、完成后的历史/角色/声音一致 |
| T11 | 刷新页面找回草稿；切换世界后主动取回旧草稿 | 不丢草稿，不自动发送旧内容 |
| T12 | 在窄屏或仅键盘条件下完成一次设置与返回 | 焦点、字号、触控范围、遮挡、可滚动性 |

## 放行条件

- 关键任务无指导完成率目标至少 90%；小样本只用于发现具体问题，不推断总体人群比例。
- 误触发送、静音失效、不可恢复数据丢失、错误世界内容混入应作为阻断问题处理。
- 本地反馈、服务确认、首段对白与音频就绪分别测量。观察面板提供本页最近操作耗时，不记录正文；模型网络延迟不能当作界面耗时。
- 对比度、字幕可读性与真实设备帧率需要实际设备检查；自动浏览器通过不等于无障碍认证。
- 对每个失败记录复现步骤和后续结果；不要仅用平均满意度掩盖关键任务失败。

招募、联系参与者和分享测试链接需项目负责人另行安排。当前自动测试与真实模型抽查不替代这些研究结果。
